# Experience design

1. Read the feature contract, existing screens, design system, analytics, user feedback, and current working flows. In brownfield work, preserve useful established patterns unless evidence justifies change.
2. Define the journey by user intent: entry, orientation, first value, repeated value, recovery, and return.
3. Build the information architecture, screen inventory, role differences, primary actions, and state matrix before discussing colors or decorative style.
4. Cover loading, empty, error, permission, offline/degraded, destructive confirmation, retry, undo, accessibility, localization, responsive/native layout, and long-content behavior.
5. Delegate an independent review to `auto-company:ux-critic` after the first draft.
6. Generate two or three distinct visual directions. When UI UX Pro Max, Interface Design, gstack design review, Expo design system, or another approved design skill is installed, use it as a specialist—not as a new source of product requirements.
7. Recommend one direction, explain why it fits the product and users, and persist it in `.auto-company/ux/ux-spec.md` or the project design-system file.
8. For dashboards, prioritize decision-making, scanability, data provenance, comparison, filters, and actionable states. For mobile, prioritize native behavior, reachability, interruption, permissions, offline behavior, dynamic text, and real-device validation.

Reject generic AI aesthetics, identical card grids without hierarchy, decorative charts, arbitrary gradients, inconsistent tokens, and screens that omit failure states.
